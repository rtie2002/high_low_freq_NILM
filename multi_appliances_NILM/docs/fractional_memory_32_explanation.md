# Fractional Front-End `memory: 32`

This note explains the theory behind:

```yaml
fractional:
  memory: 32
```

in `config/models/multinilm_fractional.yaml`.

## What `memory` Means

The fractional front-end uses fixed Grunwald-Letnikov fractional derivative filters before the MultiNILM backbone.

For one fractional order `alpha`, the ideal discrete fractional derivative is:

```math
(D^\alpha x)[t]
=
\frac{1}{h^\alpha}
\sum_{j=0}^{t}
(-1)^j { \alpha \choose j } x[t-j]
```

where:

| Symbol | Meaning |
|---|---|
| `x[t]` | aggregate mains signal at time `t` |
| `alpha` | fractional order, e.g. `0.125 ... 1.0` when `k: 8` |
| `h` | sample step, default `1` in this code |
| `j` | lag index into the past |
| `(-1)^j binom(alpha, j)` | fractional filter weight |

The binomial term is:

```math
{ \alpha \choose j }
=
\frac{\Gamma(\alpha+1)}
{\Gamma(j+1)\Gamma(\alpha-j+1)}
```

In code, these weights are generated by the recurrence:

```math
w_0 = 1
```

```math
w_j = w_{j-1}\frac{j-1-\alpha}{j}
```

so:

```math
w_j = (-1)^j { \alpha \choose j }
```

## Formula With `memory: 32`

The full Grunwald-Letnikov sum can look back over the whole past window. For efficient training, this repo truncates the sum to a fixed number of past samples:

```math
(D^\alpha x)[t]
=
\frac{1}{h^\alpha}
\sum_{j=0}^{J}
w_j^{(\alpha)} x[t-j]
```

where:

```math
J = \texttt{memory} = 32
```

So the actual formula is:

```math
(D^\alpha x)[t]
=
\frac{1}{h^\alpha}
\sum_{j=0}^{32}
(-1)^j { \alpha \choose j } x[t-j]
```

Because `h = 1` by default:

```math
(D^\alpha x)[t]
=
\sum_{j=0}^{32}
(-1)^j { \alpha \choose j } x[t-j]
```

This means each fractional value at time `t` uses:

- the current sample `x[t]`
- 32 previous samples: `x[t-1] ... x[t-32]`
- a total filter length of `33` taps

With the current YAML comment of 6-second samples, this is about:

```math
32 \times 6 = 192 \text{ seconds}
```

So `memory: 32` gives the fractional filters about 3.2 minutes of look-back history.

## What Effect It Has

`memory` controls how much past context the fractional derivative remembers.

### Smaller Memory, Like `32`

Effects:

- More local transient features.
- Faster computation because the convolution kernel has only `33` taps.
- Less smoothing from very old samples.
- Less edge/boundary influence inside each training window.
- Better focus on appliance switching events that happen over short periods.

Trade-off:

- May lose slow, long-decay information, especially for small `alpha` values like `0.125` or `0.25`.
- Can make the fractional feature closer to a short FIR edge detector instead of a true long-memory fractional derivative.

### Larger Memory, Like `128` or `256`

Effects:

- Longer historical memory.
- Smoother, slower-decaying fractional features.
- Better capture of gradual ramps, delayed settling, and long appliance signatures.

Trade-off:

- More compute and memory cost.
- More influence from old samples.
- Can blur sharp appliance on/off transitions.

## Relation to `alpha`

The repo uses `k: 8`, so the default fractional orders are:

```math
\alpha \in
\{0.125,\ 0.25,\ 0.375,\ 0.5,\ 0.625,\ 0.75,\ 0.875,\ 1.0\}
```

Each `alpha` produces one filtered channel.

With:

```yaml
k: 8
include_raw: true
memory: 32
```

the model input becomes:

```text
raw aggregate
+ D^0.125 aggregate
+ D^0.25 aggregate
+ ...
+ D^1.0 aggregate
= 9 channels
```

Every fractional channel uses the same `memory: 32`, but different `alpha` values create different temporal behavior:

| Alpha | Behavior |
|---|---|
| Small alpha, e.g. `0.125` | Softer, longer-memory change signal |
| Medium alpha, e.g. `0.5` | Balanced transient plus decay |
| Alpha `1.0` | Ordinary first difference, mostly sharp edges |

## Simple Intuition

For NILM, appliance events appear as changes in aggregate power. A normal derivative highlights only sharp changes:

```math
D^1 x[t] = x[t] - x[t-1]
```

A fractional derivative spreads that change over several past samples:

```math
D^\alpha x[t]
=
x[t]
- c_1 x[t-1]
- c_2 x[t-2]
- ...
- c_{32} x[t-32]
```

So `memory: 32` says:

> let each fractional feature remember appliance behavior up to 32 samples in the past, but ignore anything older.

In this config, that means the MultiNILM stem sees short-to-medium transient signatures over roughly 3.2 minutes, rather than very long fractional histories.

## Practical Summary

`memory: 32` is the truncation length `J` in the fractional derivative filter:

```math
(D^\alpha x)[t]
=
\sum_{j=0}^{32}
(-1)^j { \alpha \choose j } x[t-j]
```

Its main effect is to make the fractional front-end more local, cheaper, and more focused on recent appliance events. Increasing it gives longer memory and smoother fractional signals, but costs more computation and may blur sharp NILM switching events.
