\begin{abstract}
We reproduce the Subtask Gated Network (SGN) baseline~\cite{shin2019sgn} on the UK-DALE dataset using low-frequency (6\,s) aggregate and appliance power traces.
Two evaluation scenarios are defined: a full-record cross-house generalization study and a paper-scale few-week baseline.
Training uses houses~1 and~5; testing uses house~2 only.
One SGN model is trained per appliance (kettle, fridge, microwave, dishwasher, washing machine).
This document specifies data splits, preprocessing, model hyperparameters, loss functions, and checkpoint selection used in our implementation.
\end{abstract}

\begin{IEEEkeywords}
non-intrusive load monitoring, UK-DALE, deep learning, subtask gating, energy disaggregation
\end{IEEEkeywords}

\section{Introduction}
Non-intrusive load monitoring (NILM) estimates individual appliance power from a single aggregate meter.
Subtask Gated Networks (SGN)~\cite{shin2019sgn} address this with two coupled branches: a regression head for normalized appliance power and a classification head for ON/OFF state, combined via soft gating.
We evaluate SGN on UK-DALE~\cite{kelly2015ukdale} as a reproducible baseline for multi-domain NILM research in this repository.

\section{Dataset and House Selection}
UK-DALE provides whole-house and sub-metered power at 6\,s resolution.
SGN targets five appliances: kettle, fridge, microwave, dishwasher, and washing machine.

\begin{tabular}{@{}lcc@{}}

\midrule

Shin \textit{et al.}~\cite{shin2019sgn} train on houses $\{1,3,4,5\}$ and test on house~2 using the last week of each house.
We use houses $\{1,5\}$ for training because houses~3 and~4 do not provide all five appliances with sufficient coverage.
House~2 remains the unseen test house to preserve cross-house generalization.

\subsection{Scenario A: Full-Range Cross-House Evaluation}
Train on the complete available low-frequency records from houses~1 and~5.
Test on the complete house~2 record.
This scenario maximizes training data but increases preprocessing time and memory (house~1 alone is $\sim$21.6\,M samples at 6\,s).

\subsection{Scenario B: Few-Week Paper-Scale Baseline}
Train on the last 14 calendar days from each of houses~1 and~5.
Test on the last 7 calendar days from house~2.
This aligns more closely with the one-week evaluation window in~\cite{shin2019sgn} while keeping a slightly longer training window for houses~1 and~5.

\subsection{Optional Sanity Check}
A same-house temporal split on house~5 (e.g., first 85\% train, last 15\% validation) can be used to verify that the pipeline learns before interpreting cross-house test results on house~2.

\section{Data Preprocessing}
Low-frequency CSV files are produced by \texttt{ukdale\_processing\_multi\_appliance.py} from raw UK-DALE HDF5.
Each row contains aggregate power, per-appliance power, per-appliance ON labels, house ID, and a readable timestamp.
Sampling interval is 6\,s.

\subsection{Export Commands}
\textbf{Scenario A} (one CSV per house):
\begin{verbatim}
python ukdale_processing_multi_appliance.py \
  --split_houses 1,2,5 --full_range \
  --output_dir "../NILM_model/data"
\end{verbatim}

\textbf{Scenario B} (per-house truncated exports, then merge train houses):
\begin{verbatim}
# House 1 and 5: last 14 days; House 2: last 7 days
python ukdale_processing_multi_appliance.py \
  --house 1 --last_days 14 ...
\end{verbatim}

Training CSVs concatenate houses~1 and~5; test CSVs contain house~2 only.

\subsection{ON/OFF Labels}
Labels are precomputed offline using appliance-specific power thresholds (Algorithm~1 style) from \texttt{config/preprocess/ukdale.yaml}:
\begin{equation}
o_t =
\begin{cases}
1, & P_t \geq \tau_{\mathrm{appliance}} \\
0, & \text{otherwise}
\end{cases}
\label{eq:onoff}
\end{equation}
Table~\ref{tab:thresholds} lists default thresholds.
The original SGN paper uses a fixed 15\,W rule on Kelly's NeuralNILM export~\cite{kelly2015neuralnilm}; our CSV pipeline uses the YAML thresholds instead.

\section{Train, Validation, and Test Splits}
Holdout evaluation keeps all of house~2 for test.
Training windows are drawn from the concatenation of houses~1 and~5.

\subsection{Recommended Validation: Temporal Split}
Validation uses the last 15\% of the \emph{combined} train timeline (\texttt{val\_mode: temporal}, 85/15 split).
This avoids selecting checkpoints on house~5 tail data that may not reflect house~2 test behavior.

\begin{equation}
\mathcal{D}_{\mathrm{train}} \cup \mathcal{D}_{\mathrm{val}} = \mathcal{D}_{\mathrm{house\,1}} \cup \mathcal{D}_{\mathrm{house\,5}}, \quad
|\mathcal{D}_{\mathrm{val}}| = 0.15\,|\mathcal{D}_{\mathrm{train}} \cup \mathcal{D}_{\mathrm{val}}|
\end{equation}
\begin{equation}
\mathcal{D}_{\mathrm{test}} = \mathcal{D}_{\mathrm{house\,2}}
\end{equation}

\subsection{Alternative Validation: House-Tail Split}
An alternative (\texttt{val\_mode: by\_house\_tail}) holds out the last 7 days of house~5 only:
\begin{equation}
\mathcal{D}_{\mathrm{val}} = \{ x \in \mathcal{D}_{\mathrm{house\,5}} : t(x) \geq t_{\max}^{(5)} - 7\,\mathrm{days} \}
\end{equation}
This matches an earlier configuration but can mismatch the house~2 test distribution.

\section{SGN Model and Training Objective}
We follow the SGN architecture in~\cite{shin2019sgn}: six convolutional layers, a 1024-unit fully connected layer, dual regression/classification branches, and soft gating.
Input window length $L_{\mathrm{in}} = 432$ samples ($\sim$43\,min); output length $L_{\mathrm{out}} = 32$ samples ($\sim$3\,min).

Aggregate power $x$ and appliance power $p$ are normalized by the training-set standard deviation $s$ of aggregate power: $x' = x/s$, $p' = p/s$.
The regression branch outputs $\hat{p}$; the classification branch outputs ON probabilities $\hat{z} = \sigma(f_{\mathrm{cls}}(x'))$.
Soft-gated prediction is $\hat{y}_{\mathrm{gated}} = \hat{p} \odot \hat{z}$.

Per-window loss:
\begin{equation}
\mathcal{L} = \underbrace{\mathrm{MSE}(\hat{y}_{\mathrm{gated}},\, p')}_{\mathcal{L}_{\mathrm{out}}}
+ \underbrace{\mathrm{BCE}(\hat{z},\, o)}_{\mathcal{L}_{\mathrm{on}}}
\label{eq:loss}
\end{equation}

Optimization uses Adam with learning rate $\eta = 10^{-4}$, batch size 16, and no weight decay (paper-faithful setting).
Early stopping uses patience 30 epochs with a minimum of 5 epochs before checkpoint saving.
The best checkpoint is selected by minimum validation $\mathcal{L}_{\mathrm{out}}$ (\texttt{early\_stop\_metric: output\_loss}), because combined validation loss can favor early epochs when $\mathcal{L}_{\mathrm{on}}$ overfits.

\section{Training Procedure}
For each appliance $a \in \{\text{kettle, fridge, microwave, dishwasher, washing machine}\}$:
\begin{enumerate}
\item Load train/val CSV (houses~1+5) and test CSV (house~2) for Scenario~A or~B.
\item Train SGN with \texttt{--appliance} $a$ and \texttt{sgn\_paper.json}.
\item Save \texttt{best\_}$a$\texttt{.pt} by validation $\mathcal{L}_{\mathrm{out}}$.
\item Report test metrics on house~2: MAE (power), F1 (ON/OFF), and waveform plots.
\end{enumerate}

Example command (cross-house validation on house~2):
\begin{verbatim}
python main.py --model sgn --mode train_inference \
  --data_source csv \
  --csv_config baseline/SGN/configs/\
    training_data_ukdale_cross_house.json \
  --model_config baseline/SGN/configs/\
    sgn_ukdale_cross_house.json \
  --run_dir runs/sgn_ukdale_cross_house
\end{verbatim}

\section{Expected Outcomes and Interpretation}
Scenario~B provides a fast, paper-comparable baseline; Scenario~A tests whether additional training history improves house~2 generalization.
Cross-house performance on microwave and kettle (sparse ON events) is typically harder than on fridge or dishwasher.
If train classification loss collapses while validation or test F1 remains low, consider diagnosing label thresholds, stride-induced undersampling of ON windows, or domain shift between houses~1/5 and~2 rather than assuming corrupted CSV exports.
