# Stage 1 参考波形编码器：数据、训练和验证

Stage 1 的任务是把一次**已知类别的单电器事件**编码成一个 128 维参考向量。当前模型用五分类任务训练这个向量。项目的最终目标是让 Stage 2 利用独立参考波形，从全屋总功率中估计目标电器的功率和开关状态。

## 先看当前状态

较早的 `training.py` 在切片前没有给 `power_watts` 赋值，因此读取水壶 CSV 后会报 `NameError`。当前代码在读入 CSV 后通过 `power_watts = samples["appliance_power_w"].to_numpy()` 修复了这一步。训练机需要同步更新后的脚本。 [训练脚本](stage1/training.py)

当前本地快照记录了 **134,863 个事件**，其中 **2,547 个事件**标为边界截断或缺少一侧 OFF 上下文。训练会拒绝这样的旧导出。训练机的数据可能已经重新生成，可用 `--check-data-only` 检查当前版本。 [事件提取器](<dataset/appliance_waveform reference/applainces_event_selection.py>)

首轮 H6/H10 实验验证交叉熵从 1.611 升到 2.866（第 15 轮）。后续加入 H7、关闭逐事件 BN 并平衡类别与房屋后，第 7 轮验证准确率达到 92.2%。这项成绩来自原有训练/验证协议。当前 8／3／3 划分新留出 H4/H13/H16，需重新训练并另行评分。

## 1. 原始数据怎样变成一个 batch？

### 一个事件，就是一个训练样本

参考数据已经放在 `dataset/appliance_waveform reference/`。提取脚本先把源数据放在 8 秒网格上，再输出每类电器的 `events.csv` 和一份总的 `manifest.csv`。训练只读取这些导出文件。 [事件标签说明](<dataset/appliance_waveform reference/event_label_definitions.md>)

1. `manifest.csv` 每行记录一个事件，包括 `event_id`、数据集、房屋、文件名和该事件在文件内的行范围。
2. 训练脚本按类别读取 CSV 的 `appliance_power_w` 列，再按行范围取出整条事件。源文件中的结束行是**包含**的，所以 Python 切片用 `sample_end_row + 1`。
3. 事件来自哪个电器文件，就得到哪个类别标签。顺序是 `kettle=0`、`fridge=1`、`dishwasher=2`、`washing_machine=3`、`microwave=4`。洗衣机目录名是 `washingmachine`。
4. 如果导出事件包含开机前、关机后的实测上下文，或周期内部的暂停，训练会一起读取。模型输入只包含单电器功率，房屋和事件编号用来追踪来源。

### 一个 batch 可以包含不同电器、不同长度

默认 `BATCH_SIZE=20`。组批时得到一个**由 20 条一维张量组成的 Python 列表**，另外得到一个长度为 20 的类别标签张量。水壶可能有 12 个点，微波炉只有 3 个点，洗衣机有 600 个点。它们可以进入同一批，原来的长度都会保留。

`WeightedRandomSampler` 给每个事件的权重为 `1 / (该类房屋数 × 该类在该房屋的事件数)`。五类的总抽样权重相同，同一类别内各房屋的总权重也相同。例如，一户的大量冰箱事件不会压过同类的其他房屋。每批的实际类别数会变化，事件也可以重复抽到。默认一轮为 **100 批，即 2,000 次有放回抽样**。

### 一条波形真正进入模型后

| 步骤 | 尺寸 | 含义 |
|---|---|---|
| DataLoader 给出一条事件 | `[L]` | `L` 个归一化功率点 |
| 整理卷积输入 | `[1, 1, L]` | 1 条事件、1 个通道、`L` 个时间点 |
| 三层一维卷积 | `[1, 32, L] → [1, 64, L] → [1, 64, L]` | 默认每层为卷积 → 线性整流（ReLU），时间长度保持 `L`。可启用批归一化（BN）作对照 |
| 沿整段时间池化 | `[64] + [64] → [128]` | 每个通道取一次平均和一次最大值 |
| 全连接层 | `[128] → [128]` | 得到这一条事件的参考向量 |
| 逐条编码后堆起来 | `[B, 128]` | 一批所有事件的参考向量 |
| 当前的分类层 | `[B, 128] → [B, 5]` | 每条事件有五个原始类别分数 |

整个模型只有一个共享编码器。五类事件都经过相同的卷积权重。开启 BN 时，训练按**单条事件**的时间位置计算统计量，验证用累计值。短长事件混合时，这会造成训练和验证特征分布不一致。新版训练默认关闭 BN，并把这个设置存入 checkpoint 的 `use_batch_norm`。读取权重时应使用对应设置。旧 checkpoint 来自开启 BN 的版本。 [模型代码](stage1/model.py)

## 2. 归一化和数据流程是否正确？

先按房屋划分，再只用训练事件估计一套共同的 Z-score 均值和标准差：

```text
归一化功率 = (功率 W - 训练均值 W) / 训练标准差 W
```

- 五类事件共用同一套参数，保留设备之间的相对功率差异。先对每条事件的时间点取均值或平均平方偏差，再按训练抽样权重加权。类别、类别内的房屋和房屋内的事件依次等权，长事件不因采样点更多而额外主导尺度。
- 验证波形沿用训练的均值和标准差。Stage 1.5 生成参考向量时，也要使用 `best.pt` 里的同一套参数，并把编码器设为 `eval()`。checkpoint 的 `offset` 是均值，`scale` 是标准差。
- DataLoader 做 Z-score，`model.py` 直接接收归一化波形。Z-score 产生负数是正常的。模型里的 BN 处理的是卷积特征。

新版会检查上下文完整性、CSV 行数和 manifest 行范围、清单采样周期、每条事件最少点数、功率是否有限及训练和验证是否均覆盖五类。训练前还会核实标准差为正。清单的 8 秒是元数据，必要时可用源 CSV 的实际时间戳另行核对。

## 3. 损失函数和训练目标是什么？

当前用的是**五分类交叉熵（CE）**，实际调用为 `nn.CrossEntropyLoss()`。模型给每条事件五个分数，交叉熵把正确类别在五类中的相对分数变成一个损失。比如模型把一段洗碗机波形更有把握地判成水壶，损失会增大。每批的平均损失用来更新模型：

```python
optimizer.zero_grad()                        # 清掉上一批的梯度
_, class_scores = model(waveforms)            # 每条波形得到五个类别分数
loss = loss_function(class_scores, labels)   # 和真实电器类别比较
loss.backward()                              # 计算每个权重的梯度
optimizer.step()                             # AdamW 根据梯度更新权重
```

这里的 `labels` 对应代码中的 `true_classes`。`loss.backward()` 算梯度，`optimizer.step()` 才更新共享编码器和分类层。分类层为学习参考向量提供监督。后续建立参考库时，使用的是分类层之前的 **128 维向量**。当前代码实现的是交叉熵基线。VoiceFilter 的原版说话人编码器使用基于相似度的训练目标，未来可以把类似的损失作为单独对照。 [VoiceFilter 原论文，§2.1](https://www.isca-archive.org/interspeech_2019/wang19h_interspeech.pdf)

当前最多训练 **100 轮**，AdamW 学习率为 **0.0003**，训练设备为 CUDA。验证记录交叉熵、准确率和宏平均 F1（五类等权）。代码按最低验证交叉熵保存 `best.pt`，其中还保存每类 F1 和混淆矩阵。验证交叉熵连续 **12 轮**没有改善时提前停止。训练结束时保存 `loss_curve.png`，用于查看训练和验证是否同时改善。 [曲线绘制脚本](stage1/plot_loss.py)

## 4. 模型会不会只记住「短波形就是水壶或微波炉」？

**有这个风险，而且可以直接测。** 虽然没有把 `L` 当成一个额外的数字输入模型，但卷积看到边界，均值和最大值也会随事件长度、开机占比和 OFF 上下文变化。事件提取规则还会让类间长度分布不同。另一端的问题是，长洗碗机和洗衣机的不同阶段经过全局池化后，具体发生顺序会变得难以区分。

我对当前旧清单做了一次**只看事件点数**的诊断。先排除边界不完整事件和 REFIT H12 两个映射未确认的通道，再按 H6/H10 留出，验证每个「类别 × 房屋」最多抽 200 条。深度最多 3 的决策树只读取 `samples` 这一列，不读取功率。结果是 **52.8% 准确率、49.1% 宏平均 F1**，验证共 **1,352 个事件**。这一诊断使用旧清单且没有重跑全部事件质量筛选。它说明长度已经有预测力，具体数值应在新导出上重算，不能当成 Stage 1 模型结果。

| 电器 | 诊断中训练事件的长度中位数，含上下文 |
|---|---:|
| 水壶 | 22 点 |
| 微波炉 | 22 点 |
| 冰箱 | 115 点 |
| 洗衣机 | 485 点 |
| 洗碗机 | 596 点 |

水壶和微波炉在这个样本里长度中位数相同，诊断模型也经常把它们互相分错。**最有用的检查是让两类在相近长度下比较**：

1. 在新导出上重跑「只看长度」和「长度＋瓦特统计」两条基线，使用与神经网络相同的房屋划分和验证事件。
2. 单独看时长重叠的水壶和微波炉，以及长周期洗衣机和洗碗机。比较每类指标及混淆矩阵，确认模型是否从功率形状学到超出长度的线索。
3. 到 Stage 2，在相同数据、损失和设置下比较原始 MART、类别编号条件的 MART、波形参考条件的 MART。只有波形参考在未见房屋里改善分解指标，才能说明它给 Stage 2 带来额外价值。重点看目标电器开机时的功率误差、事件召回和误报。

**Stage 1 分类成功后，可以先用它生成参考库，作为可检验的基线。** 电器持续时间是合理线索，前提是目标总表里也能观察到相关的时间结构。当多个电器同时运行，单条参考事件的边界在总表中往往不明显，因此只会按长度分类的参考向量，可能无法改善分解。如果以后目标是传入任意参考后提取对应电器，还需要 Stage 2 使用共享的参考条件输出头，并单独测试未见电器类别。当前五分类结果只能评估这五个已知类别。

## 5. 训练和验证的房屋怎么分？

参考库来自 [现有参考波形目录](<dataset/appliance_waveform reference/>)。训练按 `(dataset, house)` 识别一栋房屋，这样 REFIT H2 和 UK-DALE H2 是两个不同来源。

| 用途 | 当前规则 |
|---|---|
| Stage 1 训练 | REFIT H1、H8、H12、H17、H18、H19、H21，UK-DALE H3。根据与训练机日志吻合的清单重算，训练池有 65,184 条事件 |
| Stage 1 验证 | REFIT H6、H7 和 H10 的参考事件。三栋房屋完全留出。H7 为冰箱和水壶各增加一个验证房屋 |
| Stage 1 测试 | REFIT H4、H13、H16，测试池有 34,361 条事件。整个测试集在训练完、冻结 checkpoint 之后评分 |
| Stage 1 全程排除 | REFIT H2、H20 和 UK-DALE H2、H5，保留给现有 MART 协议 |
| 每轮实际验证样本 | 每个「类别 × 验证房屋」最多固定抽 200 条。全量验证可把 `VALIDATION_EVENTS_PER_CLASS_HOUSE` 设为 `None` |
| Stage 1.5 参考库 | 从允许的训练来源选事件，并使用保存的训练 Z-score 和编码器权重 |

按整屋划分更贴近「能否迁移到新房屋」的问题。H6/H7/H10 用于挑 checkpoint。H4/H13/H16 从头训练时排除在训练、Z-score 和参考库之外。旧的第 7 轮模型训练时见过这些测试房屋，只能用来报告旧划分的验证结果。当前测试集约八成事件来自冰箱，正式报告应优先看宏平均 F1、每类 F1 和混淆矩阵，并同时报告总体准确率。 [当前配置](stage1/training.py)

在项目目录运行以下命令。第二条从头训练，第三条报告同一验证子集，第四条报告全部测试事件。

```powershell
python stage1/training.py --check-data-only
python stage1/training.py
python stage1/evaluate_embeddings.py --split validation
python stage1/evaluate_embeddings.py --split test
```

结果保存在 `results/stage1/reference_encoder_8_3_3/`。默认评估该目录下的 `best.pt`。如果训练生成了带编号的新目录，用 `--checkpoint` 指向对应权重。新版 checkpoint 固定三个房屋集合、验证事件 ID、每类参考数和训练时所用清单的哈希。评估使用相同 Z-score，并按固定种子从训练房屋生成参考库。测试报告为 `embedding_test.md`，包含五分类头与余弦匹配的结果及两张混淆矩阵。 [向量评估脚本](stage1/evaluate_embeddings.py)
